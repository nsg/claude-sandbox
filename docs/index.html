claude-sandbox

Run Claude CLI, Codex, opencode and T3 Code in a Podman container with a full development toolchain.

#A personal toolbox

I built claude-sandbox for my own needs. The tools, scripts, and features in it are the ones I use, and the bundled skills — Git, Rust, testing, delegating between model vendors, and more — are written to be generic but follow how I work.

See it as a toolbox of tools, techniques, and ideas rather than a general-purpose product. If you want something similar, my recommendation is to clone the repository and ask your own AI agent to make a version for you. To pull in later changes from here, have the agent rebase your changes on top of mine — or take your copy in a completely different direction.

Suggestions and pull requests are welcome, but there is no promise that I will merge them: this is my project, built for my needs. If you want something merged, open an issue and we can discuss it.

claude-sandbox wraps Claude CLI, OpenAI Codex CLI, opencode, and t3code in a Podman container with a full development toolchain. It mounts your current directory to /workspace and your ~/.claude, ~/.codex, and ~/.config/opencode configs into the container, keeping your host system clean while giving each agent access to everything it needs.

The binary handles container image pulls, self-updates, and skill updates automatically.

Why the name? claude-sandbox started as a sandbox around Claude Code alone. It has since grown to run Codex, opencode, and T3 Code too, but the name stayed for historical reasons. These days I mostly use it through T3 Code, which runs the different harnesses for me from a web browser or its mobile app.

#Features

  • Sandboxed GitHub CLI — proxied gh access with an audited command allowlist and launch-snapshotted write targets
  • SSH fetch bridge — fetch the launch repository's SSH origin with your host keys, which never enter the container
  • Portal approvals — approve pushes, private SSH fetches, and cross-repository GitHub actions from a PIN-protected admin portal
  • Git push bridge — opt-in pushes of the launch repository, executed on the host
  • Virtual machine bridge — opt-in creation and control of ephemeral Incus VMs without exposing host credentials or devices
  • Managed configuration — ships default AGENTS.md instructions while preserving your customizations
  • Per-project memory — auto-memory is isolated per repository, not shared across all containers
  • MCP servers — pre-configured Playwright with headless Chromium
  • Image builds — build OCI images from a Containerfile or Dockerfile with Buildah, without a daemon or extra privileges
  • Agent-controlled GUI — a headless Xvfb virtual display with Openbox, window management, screenshots, input, and accessibility-tree tools for Claude and Codex
  • Live display — view and control the sandbox's virtual X display from the admin portal through the existing portal port, no extra ports
  • GNOME usage indicator — optional top-bar extension showing plan-limit usage for every provider
  • Wrapped sessions — run the command in a tmux session, inject keystrokes and read the screen from outside with wrap-type / wrap-key / wrap-read
  • Auto-updates — binary, skills, and container image updates are checked on every launch
  • Port exposure — forward ports from the container with -p

#Quick start

Requires Podman.

Download the binary and place it in your PATH:

curl -fsSL https://github.com/nsg/claude-sandbox/releases/latest/download/claude-sandbox -o ~/bin/claude-sandbox
chmod +x ~/bin/claude-sandbox

Run it to open an interactive login shell. Claude Code, Codex, and opencode are installed; start claude, codex, or opencode from that shell:

claude-sandbox

Continue with command-line usage, or pick a topic from the menu.
